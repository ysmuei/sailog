# SaiLog · 사이로그

**Read Between the Lines — 우리 사이를 기록하다.**

카카오톡 대화 내보내기 파일에서 두 사람의 연락 패턴을 읽는 로컬 분석 웹사이트입니다. Vite + React + TypeScript SPA이며 백엔드·회원가입·외부 AI 호출이 없습니다.

## 실행

Node.js 22.12 이상을 권장합니다. 개발 환경에서는 Node 24로 검증했습니다.

```sh
npm install
npm run dev
```

표시된 로컬 주소(기본 `http://127.0.0.1:5173`)를 엽니다. Windows PowerShell에서 실행 정책이 `npm.ps1`을 차단하면 정책을 바꾸지 않고 `npm.cmd install`, `npm.cmd run dev`를 사용하세요.

```sh
npm run lint
npm run test
npm run build
npm run preview
```

브라우저 통합 테스트는 처음 한 번 브라우저를 설치한 뒤 실행합니다.

```sh
npx playwright install chromium
npm run test:e2e
```

첫 화면의 **샘플로 체험하기 → 분석 시작하기**로 파일 없이 체험할 수 있습니다. 샘플은 2026년 5~10월의 가상 메시지이며 모든 수치는 실제 통계 엔진이 계산합니다. 화면에서 가상 데이터임을 표시합니다.

## 구현 기능

- TXT·CSV·ZIP 파일 선택, 드래그 앤 드롭, 형식·크기 검사, 단계별 진행률, 업로드 취소, 오류 안내.
- 참여자 선택, 익명 표시, 날짜 범위, 전체·최근 90일·최근 30일 필터, 1/3/6/12/24시간 세션 기준.
- 메시지 수, 대화한 날짜, 선톡 횟수·비율, 평균 답장 시간, 시간대, 최근 연락량 증감.
- 일/주/월별 연락량, 시간·요일 그래프, 날짜 히트맵, 연속 연락일, 최장 무연락 기간, 최고 활동일.
- 답장 속도 분포, 텍스트 길이, 짧은/긴 답변, 평균 세션 길이, 월별 선톡·답장·대화 길이 변화.
- 최근 30일/이전 30일 비교. 표본·기간 부족과 해석 한계를 안내.
- 모든 그래프의 공통 기간 필터, 툴팁, 키보드 탐색, 페이지가 나뉜 수치 표. 히트맵은 날짜 선택으로 수치 확인.
- Light/Dark, reduced-motion, 모바일 레이아웃, 키보드 포커스, Radix 기반 모달.
- 파싱 실패 행의 최초 위치·원인·행 수, 시스템 행 제외 내역.
- 원문·이름 없는 요약 JSON 저장, 메모리 데이터 삭제, 샘플/실제 파일 구분.
- 리포트 카드 PNG 저장: 메시지 수·선톡 비율·최장 연속 연락일과 선택 기간을 1080×1350 이미지로 저장합니다. 로즈/라벤더 색상, 저장 전 미리보기, 기본 익명화, 샘플 표시를 지원합니다.

대시보드의 **리포트 카드 저장 → PNG 이미지 저장**을 사용하세요. 대시보드의 이름 표시 설정과 독립적으로 카드가 항상 익명 상태로 열립니다. 사용자가 **참여자 이름 표시**를 직접 선택한 경우에만 이름을 포함합니다. 모달을 닫고 다시 열면 익명 설정으로 돌아갑니다. 긴 이름은 이미지 영역에 맞춰 줄여 표시합니다. 원문·원본 파일명·내부 참여자 ID는 이미지에 포함하지 않습니다. 별도의 이미지 변환 패키지나 외부 서버 없이 Canvas로 집계값만 그립니다. 앱이 다크 모드여도 저장용 카드는 밝은 브랜드 색상을 유지합니다.

답장 시간 중앙값은 화면·통계 모델·JSON에서 제거했습니다. 평균 답장 시간과 답장 구간별 분포는 유지합니다.

## 지원하는 내보내기 문법

알 수 없는 문법은 추측하지 않습니다. 현재 검증은 개인정보 없는 가상 fixture에 한정되며 카카오톡의 모든 버전·운영체제에서 내보낸 실제 파일의 호환성을 보장하지 않습니다. 다른 버전은 개인정보를 제거한 형식 fixture와 테스트를 추가해 확장해야 합니다.

### PC TXT

```text
서연 님과 카카오톡 대화
저장한 날짜 : 2026-10-02
--------------- 2026년 10월 1일 목요일 ---------------
[서연] [오전 9:00] 안녕
[도윤] [오전 9:01] 반가워
여러 줄 메시지도 이어집니다.
```

날짜 구분선, 오전/오후 또는 24시간, 발신자와 시각의 대괄호가 필요합니다.

PC에서 내보낸 다음 두 자리 연도 구분선도 별도 형식 `pc-short-year-txt`로 지원합니다.

```text
--------------- 26년 1월 1일 ---------------
[가상 A] [오전 9:00] 가상 대화
[가상 B] [오전 9:01] 가상 답장
```

이 형식의 `YY`는 명시적으로 `2000 + YY`로 해석합니다 (`26년` → `2026년`, 지원 범위 2000~2099년). 일반적인 두 자리 날짜 문자열을 추측하는 규칙은 추가하지 않습니다. 올바르지 않은 날짜 구분선 다음 메시지는 이전 날짜에 붙이지 않고 진단합니다.

### 모바일 TXT

```text
2026년 10월 1일 오후 11:59, 서연 : 안녕
2026. 10. 2. 오전 12:01, 도윤 : 반가워
```

한국어 날짜 또는 숫자 연/월/일과 명시적인 시각, 쉼표, 발신자, `:` 구분을 지원합니다. AM/PM도 처리합니다. 시스템 알림은 알려진 문법만 제외합니다.

### CSV

첫 행이 정확히 `Date,User,Message`인 문법을 지원합니다. PapaParse로 쉼표·따옴표·여러 줄을 처리합니다. 발신자가 빈 행은 시스템 행으로 제외합니다.

```csv
Date,User,Message
2026-10-01 09:00:00,서연,"안녕, 좋은 아침"
2026-10-01 09:01:00,도윤,"반가워 ""친구"""
```

가상 파일: [PC TXT](public/examples/pc-chat.txt), [모바일 TXT](public/examples/mobile-chat.txt), [CSV](public/examples/chat.csv). UTF-8/BOM을 우선 해석하고 실패하면 브라우저 TextDecoder의 EUC-KR(CP949 호환)로 시도합니다. 임의의 로컬 날짜 파싱은 사용하지 않고 모든 집계를 한국 시간(UTC+9)으로 고정합니다. 불가능한 날짜를 거부합니다. 동일 시각은 원본 순서를 유지합니다. CSV의 여러 줄을 고려해 실제 시작 행을 기록합니다. 내보내기 파일에 발신자 고유 ID가 없으므로 표시 이름이 완전히 같은 사람은 구분할 수 없습니다.

### ZIP과 자원 한도

- 입력 파일 최대 20 MiB, 메시지 최대 30만 개.
- ZIP 항목 최대 100개, 전체 예상 해제 용량 최대 40 MiB, 압축률 최대 200배.
- ZIP 안의 대화 TXT/CSV는 하나만 허용합니다. 여러 개면 사용자가 파일 하나를 직접 선택해야 합니다. 중복 대화 병합을 하지 않습니다.
- 압축 해제 전에 중앙 디렉터리·암호화 여부·항목 수·크기·위험 경로를 검사하고, 추출 스트림의 실제 텍스트도 20 MiB에서 중단합니다.
- 이미지·미디어는 압축 해제하지 않습니다. ZIP64·다중 볼륨·암호 ZIP은 지원하지 않습니다. ZIP의 표시된 크기는 악의적으로 위조될 수 있으므로 스트림 제한을 함께 적용합니다.
- 처리 전체가 Worker에서 실행되며 취소 시 Worker를 종료합니다.

TXT의 일반 행은 직전 정상 메시지의 이어지는 내용으로 간주합니다. 따라서 잘못된 일반 행과 본문의 모호성은 완전히 해소할 수 없습니다. 알려진 메시지 시작 형태가 깨진 행은 본문에 합치지 않고 진단합니다. 실패 **행 수**는 누락된 **메시지 수**와 같지 않습니다.

## 통계 기준

1. 선택한 두 참여자와 날짜 범위를 먼저 적용합니다. 여러 명이 있는 대화는 선택한 두 사람의 메시지만 분석하며, 실제 1:1 채팅방과 다를 수 있음을 안내합니다.
2. 메시지 사이 공백이 세션 기준 **이상**이면 새 세션입니다. 기본 6시간. 기간의 첫 메시지도 선톡으로 계산합니다.
3. 연속된 동일 발신자를 한 발화 묶음으로 보고 **직전 발화의 마지막 메시지 → 다음 발화의 첫 메시지**를 답장 시간으로 계산합니다. 세션을 넘는 공백은 제외합니다.
4. 같은 분에 오간 메시지는 0초일 수 있습니다. 수면 시간·업무·자정 넘김은 별도 추정·보정하지 않습니다.
5. 세션 길이는 첫 메시지에서 마지막 메시지까지이며, 한 메시지만 있으면 0초입니다.
6. 평균 텍스트 길이와 짧은(10자 이하)/긴(50자 이상) 답변 비율은 텍스트 메시지만 사용합니다. 공백을 포함한 유니코드 코드 포인트 수이며 복합 이모지는 여러 자로 셀 수 있습니다. 사진·파일·삭제 메시지도 메시지 수와 연락/답장 타이밍에는 포함합니다.
7. 최근 변화는 **선택한 종료일 기준 최근 30일**과 그 이전 30일의 메시지를 비교합니다. 60일 미만이거나 이전 기간이 0개면 증감률을 표시하지 않습니다. 부분 월은 월 전체 수치로 환산하지 않습니다.
8. 연락한 날은 메시지가 1개 이상인 날입니다. 최장 공백은 선택한 범위 양 끝의 빈 날짜도 포함합니다.
9. 메시지 100개 미만 또는 대화한 날 7일 미만이면 표본 부족을 안내합니다. 숫자를 실제 호감이나 속마음으로 해석하지 않습니다.

## 구조와 개인정보

```text
src/
  app/                       앱 흐름, 테마, 지연 로딩
  components/{ui,layout,upload,charts}/
  pages/                     랜딩
  features/chat-parser/      형식별 파서, 인코딩, ZIP, 가상 데이터
  features/statistics/       순수 통계 엔진
  features/dashboard/        대상 확인·필터·네 분석 화면
  hooks/                     Worker 수명·취소·요청 식별자
  lib/                       KST 날짜·수치·스타일 유틸리티
  styles/                    세 계층 디자인 토큰
  types/                     정규화 메시지·관찰 통계·AI 확장 인터페이스
  workers/                   파싱·분석 Worker
  test/                      테스트 환경
e2e/                         Playwright + axe 통합 검증
```

원문은 Worker 메모리에서만 보유합니다. UI에는 참여자 메타데이터와 집계 결과만 전달합니다. 파일명은 원본 메타데이터에 남지만 원문과 함께 메인 화면·콘솔·서버로 보내지 않습니다. 앱은 파일 업로드 API·fetch·분석 SDK·외부 폰트/CDN을 사용하지 않습니다. React가 사용자 문자열을 텍스트로 렌더링하며 원문 HTML 삽입은 없습니다. CSP는 외부 연결과 객체 실행을 제한합니다. Vite 개발용 동일 출처 모듈 요청/WebSocket은 존재합니다.

localStorage에는 `sailog-theme-v1` 테마 값만 저장합니다. 새로고침·탭 닫기·명시적 삭제 시 앱에서 대화 데이터에 접근할 수 없게 되며 실제 메모리 회수 시점은 브라우저가 결정합니다. 삭제는 기기의 원본 파일이나 사용자가 직접 다운로드한 요약 파일을 삭제하지 않습니다. 운영 배포에서는 애플리케이션을 신뢰할 수 있는 출처에서 제공하고 확장 프로그램·기기 보안도 별도로 관리해야 합니다.

## 검증 범위와 한계

실행한 명령, 통과 수, 검증 범위는 [구현·검증 보고서](docs/verification.md)에 기록했습니다.

Vitest는 가상 데이터로 TXT/CSV/인코딩/ZIP 방어/세션/답장/집계/표본 경고/UI 업로드를 검사합니다. Playwright는 샘플과 합성 TXT 업로드, 기간 필터, 네 분석 화면, 테마, 모달, 삭제, 외부 요청 부재, 320/375/768/1440px 넘침, reduced-motion을 검사합니다. axe로 Light/Dark와 모바일의 자동 접근성 위반을 확인합니다. 수동 스크린샷도 확인합니다.

자동 접근성 검사는 모든 보조 기술 사용성을 보장하지 않습니다. 실제 iOS/Android 기기의 터치·스크린리더·중급 기기 GPU 프레임 프로파일링과 대규모 실제 파일 호환성 검증은 후속 검증 사항입니다.

## 향후 AI 확장

[메시지·통계·AI 타입](src/types/chat.ts)은 `observed-statistics`와 `ai-inference`를 구분합니다. MVP는 AI 제공자를 구현하거나 호출하지 않습니다. 호감도·관계 유형 점수를 생성하지 않습니다.

추가 개발 시에는 별도 명시적 동의, 전송할 메시지·기간·익명화 범위 확인, 보관 기간·목적·삭제 안내, 서버 측 인증·API 키·요청 제한, 공급자 개인정보 정책을 먼저 구현해야 합니다. 분석 결과는 근거 Message ID/날짜·모델 정보와 연결하고 기본 통계와 시각적으로 구분하세요. API 키는 Vite의 공개 환경변수에 넣지 마세요.
